# Harness learnings (technical gotchas)

- `Config.setPort(3000)` conflicts with rendering. Let Remotion pick the port.
- Headlines at 140px in a condensed font overflow 1080px width; keep headlines under ~110px.
- Emoji icons render inconsistently across renderers; use SVG components.
- Step labels with different line counts misalign their numbers; fix with `minHeight`.
- Test-strip style process animations need to be much longer and more prominent than a first attempt suggests.
- The instruction file must be spelled `CLAUDE.md`. A lowercase `claude.md` loads on Windows but not inside the Linux container.
- Bash heredocs with long markdown fail in the Claude Code shell wrapper on Windows; write long files with the file tool.
- IDE diagnostics on `.md` files come from a German spell-checker and can be ignored for English documents.
- `"latest"` in `package.json` without a lockfile gives every new project a different Remotion version. Pin exact versions.
- Chrome Headless Shell is versioned with Remotion (149 since 4.0.452). After a Remotion upgrade the first render re-downloads it unless the image is rebuilt.
- Claude Code loads `CLAUDE.md` from cwd and all parents, subdirectories on demand; `.claude/rules` is only documented for cwd. `@imports` resolve relative to the importing file, max four hops.
- `.agents/skills/` is read natively by Codex (upward scan to repo root), Cursor and Copilot/VS Code. Claude Code needs `.claude/skills`.
- Copilot applies the nearest `AGENTS.md` only; Claude Code concatenates parents. Client `AGENTS.md` therefore embeds the harness block.
- Remotion license: free up to three employees. Delivering only MP4s to a client keeps the client's headcount out of the count.
- Agents under time pressure invent brand values "as a proposal to adjust later" unless a gate stops them. `scripts/check-client.sh` plus rule 40 fixed this in testing; keep the gate strict.
- `scripts/new-project.sh` must set git identity from the harness repo's local config; otherwise new client repos fall back to the global (work) identity.
- Inside sed commands, `$NAME` in double quotes is expanded by the shell before sed sees it; escape or single-quote when the literal is wanted.
- A named volume mounted on a path that does not exist in the image is created root-owned. With `remoteUser: node` the user then cannot write `~/.claude`; Claude Code fails to save OAuth tokens (EACCES), reports the login as failed, and a manually re-pasted code yields HTTP 400 (already consumed). Fix: create the directory owned by `node` in the Dockerfile so a fresh volume inherits it, install `sudo` so the `chown` in `postCreateCommand` actually works (the slim Node image has no `sudo`; `|| true` hid the failure). Existing volumes: `docker run --rm -v <volume>:/v alpine chown -R 1000:1000 /v`.
- Symlinks created inside the container on the Windows bind mount work: post-create's `.claude/skills -> ../.agents/skills` link exists and is followed (verified 2026-09-21). The `file:` dependency link for the visuals package should therefore work too; the spike still has to confirm module resolution.
- `npx remotion skills add` writes `skills-lock.json` at the repo root with source and hash per skill. It is tracked; the skill folders themselves are not.
- Remotion caches Chrome Headless Shell **per project**: it walks up from the cwd to the nearest `package.json` and uses `<that>/node_modules/.remotion`, falling back to `<cwd>/.remotion` when there is none (`@remotion/renderer/dist/browser/get-download-destination.js`). A `browser ensure` at image-build time therefore lands where no render looks, and every project downloads its own 220 MB copy. There is no env var for the browser path; the fix is `Config.setBrowserExecutable()` in `remotion.config.ts`, fed by `REMOTION_CHROME` which the Dockerfile sets to one shared copy under `/opt/remotion-browser`.
- Remotion's bundler hard-aliases `react`, `react/jsx-runtime`, `react-dom/client`, `remotion` and `@remotion/studio*` to absolute paths resolved from its own location (`@remotion/bundler/dist/shared-bundler-config.js`). Duplicate React from a linked package is therefore structurally impossible — but the aliases cover only those specifiers.
- An npm `file:` linked package resolves at runtime, because webpack follows the symlink; its *own* imports do not. Webpack resolves the symlink to its real path and looks for dependencies next to the package, so anything outside Remotion's alias list (`@remotion/transitions`, `@remotion/google-fonts`, third-party) fails with "Can't resolve X in /…/packages/visuals/src". TypeScript fails the same way, on `react` and `remotion` too. Fix in the consuming project, not the package: `"preserveSymlinks": true` in `tsconfig.json` and `resolve: {symlinks: false}` via `Config.overrideWebpackConfig`. Verified 2026-09-21 with `@harness/visuals`.
- A client project's `file:../../packages/visuals` dependency points outside its own git repository. The client repo only installs while it sits inside the harness at `projects/<client>/`, which is what `clone-project.sh` arranges. A standalone clone cannot `npm install`.
- Remotion's persistent webpack bundle cache does not notice edits to the linked `@harness/visuals` package (reached through a symlink with `resolve.symlinks: false`). After the package's `index.ts` grew from 3 to 20 exports, every client render failed with React error #130 ("element type is undefined") — the cached bundle still had the old module graph — while `tsc`, reading the live files, was clean. `--bundle-cache=false` rebuilt it and Remotion printed "Cache disabled but found. Deleting". `render.sh` and `verify.sh` now pass that flag once whenever any file under `packages/` is newer than a per-project stamp (`node_modules/.harness-visuals.stamp`). After editing the package, run through those scripts, or pass the flag by hand.
- Word-boundary renames of short identifiers collide with CSS/SVG functions: `\burl\b → footer` also turned `fill="url(#…)"` and `filter="url(#…)"` into `footer(#…)` — four broken references that TypeScript cannot see (string attributes). A still of the affected scene caught it; a rename script must exclude `url(` or be followed by a targeted render.
- The leak-gate word list matches substrings, so an innocent identifier can contain a gate word by accident: the original prop name for the stamp caption in the counterfeit-jar visual did, letter for letter, across a word boundary. Prefer renaming the identifier (now `stampText`) over weakening the gate with word boundaries — a gate that never fires by accident is worth an odd prop name. Do not quote the offending identifier in the notes either; this line used to.
- `pkill -f "remotion still"` also matches the shell that issued it when that shell's own command line contains the string (Claude Code wraps commands in an `eval`), so it kills the caller (exit 144). Kill by PID, or match on `npm exec remotion`.
- Verification frames must cover every scene a change touches. Frame 60 is the hook scene in all seven reels; a component used only in a later scene (the lab certificate here) needs its own frame — compute it from `timing.ts` plus the scene's internal offsets (composition frame = scene start − transition + offset).
- The leak gate is word-based, so a client's brand **hex values** pass it unseen: the client-repo skeleton's `theme.ts` carried the first client's accent as its "placeholder" and every new client would have started on that gold. Skeleton placeholders are now deliberately grey-on-grey with `OPEN:` markers, so an unfinished theme is visible in every render. When scrubbing harness files, grep for the client's hex values as well as its words.
- A new gate check enforces the visuals contract: `theme.ts` must export `visualsTheme`, and every `src/reels/*/Reel.tsx` must contain `VisualsThemeProvider`. Without the provider the package silently renders its neutral defaults and nothing else warns.
- `node:22-bookworm-slim` ships `curl` but **no `ca-certificates`**: every HTTPS download through curl fails with `error setting certificate file: /etc/ssl/certs/ca-certificates.crt` (exit 77) while `npm` and Node keep working from their own CA bundle. `curl -sI` hides this as HTTP 000 and looks like blocked egress. The Dockerfile installs `ca-certificates`; in a running container `sudo apt-get install -y ca-certificates` fixes it at once.
- Piper voices output at their training sample rate — `thorsten-high` 22.05 kHz, the `low` voices 16 kHz, mono. The voiceover pipeline resamples every clip to 48 kHz before measuring or placing it, and keeps a 16 kHz mono copy for whisper.cpp, which accepts nothing else.
- A delivered reel (the test-strip version) used emoji as step icons — the exact failure mode rule 20 names. Nothing caught it because the rule predates the reviewer. New versions replace them; the reviewer checklist includes the check.
- `installWhisperCpp({to})` from `@remotion/install-whisper-cpp` treats an **existing** target folder as "already installed" and returns without cloning or building. Creating the folder first (or downloading the model into it first) leaves you with a model and no `main` binary, and `transcribe()` dies with `spawn …/.whisper/main ENOENT`. Install first, into a folder that does not exist yet; then download the model into it. `printOutput: false` hides the skip.
- Captions must show the approved script and take only their **timings** from the transcription. Raw whisper output of a TTS clip is a recognition of a synthesis: for the proof reel it turned the product name and the word for test strips into phonetic misspellings. The pipeline aligns script words onto the heard timeline by cumulative character position; the diff between heard and script is printed as a pronunciation report ("heard: … ← check pronunciation") and is the cheapest TTS quality check we have. Do not quote the misheard product name in harness notes — this line used to.
- Shell quoting: a `node -e '…'` one-liner cannot contain single quotes. Patches with JS strings go into a `.mjs` file first (heredoc with a quoted delimiter), then `node file.mjs`.
- Remotion gives Chrome a fixed 25 s to come up (`BrowserRunner`: "Timed out after 25000 ms while trying to connect to the browser"). After heavy disk I/O — a 487 MB model download, a whisper.cpp build, a rebuilt image whose 220 MB binary is not yet paged in — a cold start can exceed that, and every probe with a fresh profile hits the same wall, which looks like a broken browser. The binary is fine; the second start is warm. `render.sh`/`verify.sh` retry once on exactly that message.
- Captions (and anything that must stay on top) need an explicit `zIndex`: DOM order is not enough once a scene element sets its own z-index — the test-strip animation drew over the caption plate.
- An absolutely positioned box centred with `left: 50%` and no `width` gets shrink-to-fit width limited to the space right of its left edge (540 px in a 1080 frame) and wraps a 24-character line. Centre with `left: 0; right: 0; margin: auto; width: fit-content` instead.
- Caption paging limits are per **page**, and a page wraps into two lines: a 34-character limit produced one-line pages that split phrases; ≈ 60 characters at 44 px in 860 px gives two full lines. Keep numbers with their units when breaking.
- Spoken and written text differ ("H zwei O zwei" vs "H₂O₂", "example Punkt d e" vs "example.de"): the manifest needs both, or the TTS spelling ends up in the captions.
- A caption that repeats the scene's own headline (hook, CTA) adds clutter and collides with the layout; leave it out where the spoken line is already on screen.
- Verify **layout, not just presence**: the first caption stills looked fine until frames were chosen where scene content lives in the caption band. Choose frames per scene where the busiest content and the caption coincide.
- Keeping every historical reel version renderable has a legal side: versions that predate a client's legal line still carry the claims it later forbade, and nothing flagged them until the copy corpus of all reels was listed for a new storyboard. `check-client.sh` now scans every live reel for the phrases quoted on "Forbidden:" lines of the client's `20-legal.md` and warns with reel names; the affected reel notes say "not for re-delivery". Write new copy from the published, post-legal-line corpus first, and mark anything new for the user's approval.
- `@remotion/google-fonts` `loadFont(style, {subsets})`: the `latin-ext` subset alone covers only the extended Latin block, so basic A–Z and digits fall outside the loaded `unicode-range` and Chrome renders them in the system fallback — DejaVu Sans in this image — while umlauts come out in the intended font. Every render of the first client since March, delivered MP4s included, showed DejaVu instead of the brand font and nobody caught it by eye (a `…Wrong_font.mp4` in the deliveries suggests it was once noticed and not traced). Always load `['latin', 'latin-ext']`; tell-tale glyphs of the fallback: a serifed "1", a hooked-descender "g", a wide "?".
- The reviewer subagent's first real run found that font defect, three right-safe-zone overruns of 20–30 px and a logo drawn at 2.5× its source size — all in stills a human had just approved as "fine". Pixel evidence and measured x-positions beat impressions; keep the reviewer in the loop for every delivery.
- ffmpeg `loudnorm` in linear two-pass mode can overshoot the true-peak target by up to ~0.3 dB. `master.sh` now targets TP −1.3 so the result stays at or below −1.0 dBTP.
- Shared components with fixed intrinsic sizes (the map: 370×600, the globe: 500 wide with a 46 px single-line caption) need either a size/scale prop or a `transform: scale()` wrapper in the scene; a bigger container does nothing. A long caption in a fixed-size component is the first thing to enter the right UI zone — expose the font size as a prop.
- JSON is the wrong authoring surface for spoken text: a writer thinks in scenes and lines, not in quoted keys, and a generated `index.ts` named like source code invites hand edits that the next pipeline run erases. Author in a screenplay-shaped markdown, generate a file whose name says "generated" and whose only content is data typed from the package.
- Piper output is **not** deterministic: the model samples noise, so the same text yields clips that differ by a few hundred milliseconds between runs (a 4.97 s CTA came back at 4.59 s). Never assume a re-synthesis leaves timings alone — that is why clips are cached by recipe and committed, and why `deriveVoiceTiming` re-derives every length from the index on each run.
- The `file:`-linked pipeline package resolves its own `exports` for the client (`@harness/pipeline/script` → `script.d.ts`/`script.mjs`) once the client lists it as a dependency; a `script.ts` bundled by esbuild needs the same specifier aliased to the absolute path, because the bundle is written to a temp dir where no `node_modules` resolution exists.
- `node --test <dir>` fails on a directory in Node 22 when the folder mixes test and non-test files (it tries to run the directory as a test); pass the files or a glob (`voiceover/*.test.mjs`).
- Exact pauses between TTS segments: normalise (silence-trim) each segment first, then `ffmpeg -f lavfi -t N -i anullsrc=r=48000:cl=mono` between them in one `concat` filter graph. Whisper transcribes the joined clip in one pass; the gap shows up as a caption page break when it exceeds the pager's gap threshold.
- "Caption" is ambiguous in a video harness: the globe and map components have a `caption` prop (a text drawn *inside the scene*), while the audio pipeline used "caption" for the burnt-in transcript of the voice. The user read the script's `> caption:` as the scene's on-screen copy. The authoring surface now says **subtitle** (`> subtitle:`, `<Voice subtitles subtitlesBottom/>`, `VoiceScene.subtitle`); the rendering component keeps its technique name `Captions`. Name a text by *where it appears*, not by the technique that draws it.
- A generated index that a reel imports must exist before the first `tsc`, or a fresh reel cannot compile until the voiceover has run. `scripts/new-reel.sh` writes a placeholder index (`source: "placeholder"`, no scenes); `deriveVoiceTiming()` then yields the designed lengths and `<Voice>` renders nothing for that source only — a real index with a missing scene still throws.
- `scripts/new-project.sh` copied the format template with `cp -r "$TEMPLATE/."` — fine while templates had no `node_modules`, but post-create now installs them, so a new project copied ~150 packages file by file across the Windows bind mount (still running after nine minutes) before its own `npm install`. Copy templates with `tar --exclude=./node_modules --exclude=./out`; anything installed is re-created by `npm install` in the new project.
- A hard-coded `DURATION_FRAMES` that equals the plain sum of scene lengths ignores the `TransitionSeries` overlaps and renders the difference as pure black at the end — 42 frames (1.4 s) in two delivered reels, unnoticed since April because nobody measured the tail. Derive the total from the scenes minus the transitions (`deriveVoiceTiming` does; hand-written `timing.ts` must too) and check the last frame's luma (`ffmpeg -sseof -0.04 … signalstats`, YAVG ≈ 0 means black) before delivery.
- Project hooks (`.claude/settings.json`) are loaded at session start; a hook added mid-session does not fire until the session is restarted (a live `git push` test right after writing the deny hook went through to git's own "no remote" error). Test new hooks by piping a crafted JSON input into the script (`echo '{"tool_input":{"command":"git push"}}' | node .claude/hooks/deny-push.mjs`), then restart.
- `ffprobe -of csv=p=0` appends a trailing comma to single-field lines and can print more than one line per stream query; pipe through `head -1 | tr -d ','` before arithmetic, or `30/1,` becomes `30-nan`.
- The client-gate hook found what the sync habit missed within minutes: a harness rule edit had left the client's `AGENTS.md` stale (only the harness was re-synced), so `check-client.sh` was NOT READY without anyone noticing. The sync hook now regenerates the right layer on every rule edit; the harness edit still needs a client sync when the embedded harness block changes — the gate catches that.
- Hook input carries `cwd` (Claude's directory), not the shell command's own `cd`; a hook that must know which repository a `git commit` targets has to parse `git -C <dir>` or a leading `cd <dir>` out of the command and fall back to `cwd`.
- An async PostToolUse hook that type-checks after every edit needs a per-project lock (a batch of edits would start one `tsc` each); the lock skips overlapping runs and expires after 90 s so a crashed run cannot silence the hook.
- The format templates are not meant to be installed: only `templates/insta-reel` carries `node_modules` (post-create installs it) because the type-check hook and the pipeline's loader test use it as the harness-side consumer of the linked packages. Installing all three to refresh lockfiles cost 1.2 GB on the bind mount; use `npm install --package-lock-only` for a lockfile-only update, and delete `node_modules/.cache` (webpack, 160 MB) after probe renders in a template.
